01 · Clear Problem Statement

Why Applied AI storage platforms break privacy & compliance SLAs when customer prompts, opt-out toggles, and foundation-model training shards are decoupled.

AWS Applied AI Core Storage Challenge
FAILURE MODE 01

Silent Opt-Out Drift into SFT Shards

Enterprise customers toggle AI training consent asynchronously, while nightly batch pipelines copy raw event logs into vector stores and SFT/LoRA manifests—leaking opted-out tenant prompts into model weights.

FAILURE MODE 02

Raw PII & Over-Privileged Data Reads

Without pre-ingestion VPC PII tokenization and purpose-bound role gates, analytics engineers and ML training jobs read unredacted SSN, EMAIL, CARD, and AKIA credentials stored under a single shared bucket key.

FAILURE MODE 03

Unverifiable GDPR Art. 17 / CCPA Deletion

Deleting rows in a primary table leaves orphaned copies across append-only partitions, feature stores, and historical training snapshots—failing regulatory erasure audits with no cryptographic proof of destruction.

02 · Excalidraw Architecture & How It Works (30s Walkthrough)

100% serverless AWS topology (CloudFront → private S3 OAC + Python 3.12 Lambda + SQLite WAL + Amazon Bedrock Nova) with every stage metric measured in benchmarks/latest_results.json.

STEP 01 / ENVELOPE & PII

Per-Tenant KMS DEK + PII Vault

Tokenizes 6 PII classes via tenant-salted HMAC-SHA256 and seals raw + sanitized payloads in separate AEAD envelopes bound to tenant|event|cmk_arn at 5,182.4 ev/s.

STEP 02 / CONSENT GATE

Real-Time ML Opt-Out Controls

Tenants flip between ALLOW_ML_TRAINING, ANALYTICS_ONLY_OPTOUT_ML, and STRICT_ZERO_RETENTION, triggering immediate SQLite feature_shard_lineage eviction.

STEP 03 / SNAPSHOT ACL

Purpose-Bound Dataset Builder

Enforces caller role × dataset purpose in 0.028 ms p50, building sealed ML snapshots in 15.09 ms with 0.0% opted-out leakage across 1,200 events.

STEP 04 / CRYPTO-SHRED

RTBF Cascade & Bedrock Audit

Zeroizes tenant 256-bit KMS DEKs and purges downstream SQLite shards in 2.805 ms mean, then calls live Bedrock Nova (2,923 ms p50) for compliance attestation.

03 · What I Implemented (`vault_lineage/`)

Zero-dependency Python 3.12 core engine (`vault_lineage/storage_engine.py`, `server.py`, `benchmarks.py`) verified by 10/10 `unittest` suites and live AWS CloudFront deployment.

10 / 10 Unit Tests Passing (0.14s)

1. `KmsEnvelopeKeyring` + Dual-Envelope SQLite Partitions

Generates per-tenant 256-bit CMK wrapping secrets and 256-bit DEKs, encrypting every event into two distinct AEAD envelopes (`raw_envelope_json` for security auditors, `sanitized_envelope_json` for ML/analytics) inside indexed SQLite WAL tables (`idx_events_tenant_status`) with cross-tenant AAD tamper detection.

2. Deterministic VPC PII Tokenizer & Hash-Chained Ledger

Scans `SSN`, `AWS_ACCESS_KEY`, `CREDIT_CARD`, `EMAIL`, `PHONE`, and `IP_ADDRESS` before encryption, replacing matches with tenant-isolated HMAC tokens (`<PII:SSN:4d91be07>`) and recording every mutation in SQLite `audit_ledger` (`prev_hash → entry_hash`).

3. Real-Time Opt-Out Gate & Purpose-Bound Snapshot Builder

`build_training_snapshot()` validates `ROLE_CATALOG × PURPOSE_POLICIES` (`403` on role mismatch) and executes a live SQLite `JOIN` over `encrypted_events` and `tenants`, admitting only `ALLOW_ML_TRAINING` active partitions for SFT/LoRA while quarantining `ANALYTICS_ONLY_OPTOUT_ML` and `STRICT_ZERO_RETENTION`.

4. Irreversible RTBF Crypto-Shredding + Live Bedrock Auditor

`delete_tenant_rtbf()` zeroizes in-memory CMK/DEK bytearrays (`0x00`), tombstones SQLite partitions, purges `feature_shard_lineage` and historical ML snapshots (`manifest_sha256` re-sealed), signs an `HMAC-SHA256` Deletion Certificate, and invokes `us.amazon.nova-lite-v1:0` via `boto3` `converse()`.

05 · Why It Wins (Architectural Trade-Offs)

          

            Comparing VaultLineage's per-tenant KMS crypto-shredding & SQLite lineage DAG against conventional AI data-lake architectures.
          

        

        Zero-Serverless Footprint (No EC2 / RDS / GPU)
      


      

        

          
            

              Architecture Pattern
              Tenant Encryption Isolation
              Real-Time ML Opt-Out Enforcement
              GDPR / CCPA Deletion Across ML Shards
              Audit & Compliance Proof
            

          
          
            

              1. Naive Append-Only Object Lake + Ad-Hoc Row Deletes
              Single shared bucket KMS key; cross-tenant read blast radius
              Delayed batch sync; high risk of opted-out leakage into SFT shards
              Requires rewriting multi-TB Parquet archives; misses downstream LoRA copies
              Unstructured application logs; no cryptographic proof
            

            

              2. Coarse DB Table ACLs Without PII Token Vault
              Table-level encryption only; raw PII exposed to ML scientists
              Manual SQL WHERE filters prone to scientist query bugs
              Deletes primary rows while feature-store embeddings retain memorized PII
              No Merkle or HMAC deletion certificate
            

            

              3. VaultLineage (Per-Tenant KMS DEKs + SQLite Lineage Gate + Bedrock Auditor)
              Dedicated 256-bit DEK per tenant + cross-tenant AAD + dual raw/PII-tokenized envelopes
              0.0% leakage (0/1,200); instant SQLite shard eviction + role × purpose 403 gate (0.028 ms p50)
              Irreversible DEK zeroization + 100% SQLite shard & snapshot re-compaction in 2.805 ms
              1,374/1,374 SHA-256 hash-chained entries + HMAC Deletion Cert + Live Bedrock Nova Memo
